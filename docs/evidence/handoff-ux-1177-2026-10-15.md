## 2. Gaps against the task (this PR)

1. The four modes share one layout; only the chip text and tone differ. The user cannot tell at a glance who holds the session.
2. No authenticated-observation consumer: coordination is unreachable by construction, so nothing can ever enable.
3. Job and descendant cancel are one disabled row each; no per-job target binding, no pending-until-confirmed state.
4. Approvals are a boolean badge. No progress, artifact or capability evidence.
5. A transport failure after the request left is shown as a plain failure ("failed, retry"), not as an unknown outcome.
6. Return-to-user does not say why the lead let go (completed, cancelled by you, failed, timed out) nor where the draft and focus went.
7. The UI sits on the pre-#1385 chat layout; browser proof for no duplicate session/transcript/execution, zoom, touch, screen reader and reduced motion needs re-running on the reconciled canvas.

## 3. Done in this slice (independent of #1385 / ui #416)

New `model/handoff-observation.ts` and additive fields on `handoff.ts`, no edits to #1385 files:

- `bindTargetObservation`: an observation binds only if `source === 'runtime_authenticated'` AND session, task, generation, owning intent and owning attempt (admitted `attemptId`) all equal the claim and the live session. First disagreement returns its own code (`absent | unauthenticated | session | task | generation | intent | attempt`).
- `resolveLeadCoordination` uses it. No observation: unchanged reason text (existing tests untouched). Partial or disagreeing observation: names the missing proof. Full match: coordination binds. No production producer exists, so production stays unavailable and says why.
- `deriveChildJobRows`: per child job, cancel-job and cancel-descendants are separate from lead-stop; enabled only with bound coordination, the job's own observation binding to the same target, a cancellable state, and a wired cancel path (CP #935). `cancel_pending` stays pending, cannot be re-requested.
- `deriveHandoffActivity`: raw observed event counts from the retained window (approval requested/closed, `file.observed`, `subagent.observed`, capability degraded/restored, last event) with `activeStateKnown: false`. Events carry no qualified identity here, so open approvals and currently degraded capabilities are not inferred and the surface labels these as raw events. Counts are lower bounds when the window is incomplete; a terminal fallback reports no structured approvals; payloads are never read.
- View fields `holder` (none | lead | user), `returnedReason`, `childJobs`, `activity`.
- `outcomeUnknown` on action failures plus `isUnknownOutcome` hook: "may have been applied, check status" rather than "failed".

## 4. Mode design (to build on the reconciled #1385 canvas)

One status band above the transcript, composed from the shared `ChatNotice`/`StatusChip`/`Marker` primitives; the transcript, composer and scroller are untouched.

| Mode                                | Holder | Band says                                                                                      | Primary action                           | Never                                        |
| ----------------------------------- | ------ | ---------------------------------------------------------------------------------------------- | ---------------------------------------- | -------------------------------------------- |
| Read-only reference (`attached`)    | nobody | "Reference only. You are reading this session. Nothing here controls it."                      | Hand off to lead (if one linked channel) | grants control, forks                        |
| One-time review (`one_time_review`) | nobody | "Review pass over a finished/archived transcript. No new work starts."                         | none (reopen is elsewhere)               | enables stops                                |
| Coordination handoff                | lead   | "The workspace lead is coordinating under turn X (bound to this session, task, generation Y)." | Take back (stops the lead turn)          | cancels jobs or descendants as a side effect |
| Returned to you                     | user   | "Returned: completed / you stopped it / failed / timed out. Your draft is where you left it."  | Hand off again (when allowed)            | auto-restarts the lead                       |

Requested-but-unbound state is a fifth look inside `attached`: "Requested, not yet coordinating", with Check status; it is never drawn as coordination.

Evidence strip (under the band): approval events seen (raw requested/closed counts; a waiting state is shown only from the explicit `awaitingApproval` input, never inferred), progress (session lifecycle, run state, lead turn state, last event time), artifacts (files observed), capabilities (projection kind, raw degraded/restored events, active state unknown). Each states its window ("in the retained window" when incomplete). Nothing is drawn without a producer. Tool pairing and per-tool progress stay out (no call identity contract, per #1385).

Control rows keep the three scopes visibly apart: Stop lead (the lead turn) / Stop session run (the harness run) / Cancel job and Cancel descendants (per job, target-bound). Every disabled control keeps its `aria-describedby` reason.

## 5. Interaction matrix (rows = situation, columns = what the user sees and what is guaranteed)

| Situation                                                         | Mode / band                    | Controls                                                                                | Guarantees                          |
| ----------------------------------------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------- | ----------------------------------- |
| Session id supplied only                                          | reference                      | all disabled with reason                                                                | no coordination, no control         |
| Running lead, claim matches, no observation                       | reference + "requested"        | lead stop only if own live turn; handoff blocked (one outstanding)                      | not coordination                    |
| Authenticated observation, all five agree                         | coordination                   | lead stop, session stop; job cancel per job if wired                                    | one session/transcript/harness      |
| Observation: wrong session / task / generation / intent / attempt | reference                      | disabled, reason names the failing proof                                                | nothing enabled                     |
| Stale generation                                                  | reference ("resync")           | everything paused                                                                       | no action without resync            |
| Offline                                                           | reference ("offline")          | paused; Reconnect transcript                                                            | drafts, scroll, selection preserved |
| Handoff request, transport lost mid-flight                        | reference                      | "may have been applied" + Check status; retry safe (server dedupes the complete target) | at most one retained request        |
| Double click / two controls at once                               | unchanged                      | second is ignored while one is busy                                                     | exactly one effect                  |
| Two tabs/hosts race (conflict)                                    | refresh from exact intent      | busy clears, view re-reads                                                              | late completions fenced by epoch    |
| Lead completes / fails / times out                                | returned (reason)              | handoff available again                                                                 | composer and draft unchanged        |
| You take back (lead stop)                                         | returned: cancelled            | stop disabled; jobs untouched (shown as still running if observed)                      | descendants not cancelled           |
| Job cancel requested                                              | pending until runtime confirms | disabled while pending                                                                  | not shown as done                   |
| Archived / terminal session                                       | review                         | disabled                                                                                | history preserved                   |
| Terminal-fallback projection                                      | unchanged                      | approvals not claimed                                                                   | no structured evidence invented     |
