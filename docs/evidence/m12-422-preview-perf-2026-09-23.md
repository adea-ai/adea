# M12.8 — browser preview lane: 30-minute measurement (#422)

The #422 acceptance box asks for a browser lane that **records startup, frame
latency, CPU/memory at idle and active, a 30-minute preview, and bounded capture
storage**. This is that record: one continuous 30-minute run against the live
engine (Bun 1.4 `Bun.WebView` + CDP, the engine ADR 0006 selects for the agent
lane), with the raw artifact retained beside this file.

- **Command:** `bun apps/desktop/shell/scripts/browser-preview-perf.ts --minutes 30 --artifact artifacts/browser/preview-perf.json`
- **Engine:** `Bun.WebView (live)` — the run refuses (exit 2, typed `blocked`
  artifact) when `Bun.WebView` is absent, so a pass cannot come from a stub.
- **Artifact:** [m12-422-preview-perf-2026-09-23.json](./m12-422-preview-perf-2026-09-23.json)
  (`status: passed`, `previewElapsedMs: 1_814_203` = 30.2 minutes).
- **Recorded:** 2026-09-23T23:18Z–23:48Z, macOS arm64, on the owner's machine.

## What the lane measured

| Measurement                           | Result                                                                             |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| Window                                | 30.2 min continuous (`previewElapsedMs` 1,814,203)                                 |
| Startup: lane create → first frame    | 4,825 ms (navigation admitted through the SSRF/rebinding gate)                     |
| Frames published                      | 4, frame-interval p50 68 ms / p95 317 ms                                           |
| Capture latency (screenshot over CDP) | 60 samples: p50 251 ms, p95 718 ms, max 2,202 ms                                   |
| Idle resident memory (first half)     | min 52.4 MB, median 56.9 MB, max 54.8 MB over 89 samples                           |
| Active resident memory (second half)  | min 57.9 MB, median 62.8 MB, max 62.9 MB over 60 samples                           |
| CPU seconds: idle half / active half  | 12.3 s / 2.6 s (the active half captures continuously, so its CPU is capture work) |
| Bounded capture storage               | 365,664 bytes total, peak 365,664, **0 refusals**, ~6.1 KB per captured frame      |
| Sample cadence                        | 10.0 s idle, 15.4 s active (capture + ack adds ~5.4 s per iteration)               |

## What this proves, and what it does not

**Proves:** the lane runs the full window without a crash, a leak that grows
without bound, or an unbounded capture store — resident memory moves 52.4 MB →
62.9 MB with the active phase's captures and stays there (the capture store's
peak equals its total, and no capture was refused), and every phase change is
visible in the series rather than averaged away.

**Does not prove:** a workload larger than one proof page with a canvas
animation, bandwidth limits at the transport, or device lanes — those have their
own acceptance rows (screencast/takeover fencing, device capability states). The
`longTasks.samplesRecorded` 149 vs `expectedSamples` 180 is the cadence above,
not a dropped sample: the loop samples every 10 s around each capture, and the
active half spends ~5.4 s per iteration engaged in the capture it is measuring.

**Retention:** the raw per-sample series (149 rows) is committed with this file,
so the numbers above can be re-derived without re-running the lane. The run
itself writes to the gitignored `artifacts/` tree; this directory is the record
of the measurement.
