## Fixture assumptions vs live reality

- **`mergeable` is asynchronous on github.com.** The fixtures script
  `mergeable: true`; the real PR returned `mergeable: null` immediately after
  creation and still `null` minutes later on an inactive private repo
  (`mergeable_state "unknown"` via the REST API). The provider maps null → the
  typed `"unknown"` shape, which is exactly the #423 contract ("typed
  unknown/unavailable fields"); fixtures cannot produce this path.
- **Empty collections are real shapes.** Checks page `total_count 0`,
  reviews `[]` (→ `reviewDecision` absent), issues and milestones `[]`. The
  provider's decode/decorate paths handle all of them without failing the
  read.
- **The fence's ambiguous-delivery branch cannot be safely provoked** against
  the real host without network manipulation, so the lane proved the stronger
  property instead: the durable intent survives a registrar restart (same data
  dir, fresh authority) and refuses a re-POST, with the API showing no side
  effect — plus the real deterministic-failure path end to end, which is what
  exposed #597.

## Defect found (filed, not fixed here)

- **#597** — a deterministic create failure (real HTTP 422) leaves the durable
  PR-create intent in place, so every later create for that head/base pair
  refuses with `remote_unavailable` until the intent file is deleted by hand,
  even though GitHub provably created nothing. Fail-closed direction (no
  duplication risk), availability-only impact, manual recovery documented in
  the issue. Steps s20/s21/s25 are the live evidence; the fixture suite never
  hits it because its only scripted create failure is a timeout.

## Containment

The disposable repository is private and synthetic (seed README, three draft
PRs, no secrets, no real emails). The authenticated `gh` token lacks the
`delete_repo` scope (verified with a throwaway probe: `gh repo delete` → HTTP
403 "This API operation needs the delete_repo scope"; `gh auth refresh` is an
interactive device-code flow that this lane cannot complete), so deletion was
replaced by the closest containment: the three feature branches were deleted
via the git refs API (works under `repo` scope), the pull requests were
closed, and the repository was archived read-only via
`PATCH /repos/... {archived true}`. GitHub refuses to delete the default
branch ("Cannot delete the default branch", HTTP 422), so the residue is an
archived private shell whose `main` holds only the synthetic seed commits,
plus the empty archived probe shell. The lane script itself never deletes
anything; it refuses to run against a repository that already has remote
branches or open PRs beyond the seed.
