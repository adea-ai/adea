# M12 #426/#541 WCAG 2.2 AA automated accessibility audit — 2026-09-22

Automated axe-core audit pass for #426's completion box "Accessibility audit
meets WCAG 2.2 AA for the complete journey." Automated axe coverage is the
accepted v1 scope for the gate; manual screen-reader/keyboard certification
stays a recorded gap (see the certification package,
`docs/evidence/m12-426-certification-2026-09-22.md`).

## Method

- Lane: `bun scripts/audit-a11y-dev-view.mjs` (added this date; committed with
  this package). It drives the real served app with Playwright on the same
  pinned Chromium build as the E2E lane, injects `axe-core` 4.13.0 (new
  root devDependency, dev-only, MIT, not shipped to any runtime bundle), and
  scans with tags `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`.
- Server: the app booted exactly like the E2E web server (`cd apps/web &&
bun run dev` with the compose-Postgres `DATABASE_URL` defaults from
  `playwright.config.ts`, `PORT=3123`), audited over `http://127.0.0.1:3123`.
- Surfaces (guest-reachable, the ones the M12 owner journey crosses):

  | Surface               | What was scanned                                                                                                                                                                                     |
  | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `chat`                | Chat workspace, default view, 1280x900                                                                                                                                                               |
  | `dev-view-terminal`   | Dev View (`?view=dev&devE2e=preserved` fixture mode) with the integrated terminal pane mounted, sidebar open, 1280x900                                                                               |
  | `dev-view-narrow-320` | Dev View at 320x900 with the projects sidebar visible (narrow end of the matrix)                                                                                                                     |
  | `settings/<tab>`      | Settings dialog, scoped to `[role="dialog"]`, for every rendered tab (Account & app, Appearance, Workspace, Agents, Input & notifications, Privacy & data, Integrations & capabilities, Permissions) |

- Artifact: `artifacts/a11y/axe-dev-view-2026-09-22.json` (machine-readable:
  per-surface violations, selectors, HTML samples, totals).

## Violation details and repro selectors

### `aria-required-parent` — critical — #598

Settings dialog tab triggers carry `role="tab"` with no `role="tablist"`
ancestor, so assistive tech announces eight unrelated buttons instead of one
tab set, on every tab:

```text
button[aria-controls="settings-panel-account"]
button[aria-controls="settings-panel-appearance"]
button[aria-controls="settings-panel-workspace"]
button[aria-controls="settings-panel-agents"]
.conventional-settings-nav__group:nth-child(3) > button[role="tab"]:nth-child(3)
```

### `aria-required-attr` — critical — #600

The focusable workspace sidebar resize handle reports no value state:

```html
<div
  class="conventional-sidebar__resize"
  role="separator"
  aria-orientation="vertical"
  aria-label="Resize workspace navigation"
  tabindex="0"
></div>
```

Selector: `.conventional-sidebar__resize`.

### `color-contrast` — serious — #599

Dev View truthful-status badges and Settings nav group labels fall below the
4.5:1 minimum in the default theme (38 nodes; the per-tab repetition is the
same four nav labels):

```text
.dev-row-badge--success            ("harness")
span[title="Uncommitted changes"]  ("dirty")
span[title="Owned ports 3000"]     (":3000", narrow layout only)
.conventional-settings-nav__label  ("Account", "Workspace", "Workflows", "Data & access")
.conventional-settings-note        (Privacy & data tab)
```

## Interaction defect observed by the lane (not an axe rule) — #601

Clicking the already-selected **Account & app** tab trigger dismisses the
entire Settings dialog (`[role="dialog"]` 1 → 0). Controlled checks: inactive
tabs switch normally; the closure reproduces with and without axe injected and
after prior Dev View navigation. The audit lane therefore audits the selected
tab as rendered and only clicks other triggers; details in #601.

## Scope and gaps

- Automated axe coverage only: screen-reader (VoiceOver/NVDA), keyboard-only
  journey certification, reduced-motion/transparency, and zoom levels beyond
  the 1280/320 audit points are not covered by this pass and remain open on
  #426/#541.
- The packaged CEF shell chrome is not audited: no CEF/CDP engine publishes
  frames in the packaged app (#537), so the audit ran against the served app
  the shell embeds (same SPA build, `apps/web/dist-desktop/client` was built
  from the same source during the packaged build sequence).
- Contrast was measured in the default theme at the two audited viewports;
  other bundled themes need the same pass once the #599 token fix lands.
- Findings are recorded, with product fixes to be made in the design-system
  and shell sources (not patched by the audit lane).
