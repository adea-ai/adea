# M15 #301 performance baseline — 2026-09-23

Measured baseline for #301's acceptance list ("record cold/warm build times,
TTFB, route bundle sizes, artifact sizes, memory, and representative
LCP/INP/CLS; define budgets and go/no-go gates before migrations; separate
deploy artifacts from local build caches"). The budgets this run defines are
[ADR 0010](../decisions/0010-performance-budgets-and-gates.md).

## Method

Lane: `bun run test:performance:web` (added with this package; it runs the two
existing budget gates rather than duplicating their numbers).

- **Builds** — `bun run --cwd apps/web build` on the main checkout, macOS
  arm64. Cold clears `dist`, `node_modules/.vite`, and `apps/web/.vite` first;
  the cache-warm run restores the dep cache and rebuilds anyway (this stack has
  no incremental rebuild cache).
- **Artifacts** — byte and file counts over `dist`, the client JS surface
  (`dist/client/start-assets/*.js`), the Worker entry
  (`dist/server/index.js`), with Vite's dep cache and the Cloudflare Vite
  plugin's local `.dev.vars` copy excluded from the deploy byte count.
- **TTFB** — the built Worker booted through `bunx wrangler dev --local` on a
  loopback port with the compose-Postgres `DATABASE_URL`; one warm-up request
  then 20 measured requests.
- **Browser** — pinned Playwright Chromium 1.63, 1280×900, headless, cold
  cache: LCP and CLS from buffered `PerformanceObserver` entries, plus a
  scripted interaction burst (search, settings, Escape) whose worst
  `event-timing` duration is recorded as an **INP proxy** — real INP needs
  field data.

## Findings

1. **Client JS has 2,400 bytes of headroom.** At 99.85 % of the byte budget the
   next eager-shell addition is a budget decision, not a routine change. This is
   now ADR 0010's first go/no-go gate.
2. **The build tree carries a local secrets copy.** The Cloudflare Vite plugin
   writes `dist/server/.dev.vars` (a normalized copy of the gitignored
   `apps/web/.dev.vars`, which holds `NEON_AUTH_*` values) into the build
   output. The file is gitignored and excluded from the deploy byte count, and
   the lane's hygiene gate now allowlists exactly that path and fails on any
   other non-deploy file — so a future build step that starts emitting something
   deployable-looking is caught here rather than at upload time.
3. **"Warm build" was never a real comparison.** The retired host's 0.07 s was
   an incremental rebuild; a cache-warm run of this stack is a full transform.
   The baseline documents that so migrations cannot claim a speedup against it.

## Gaps

- LCP/CLS/interaction are lab numbers on loopback with no throttling and a
  single run. Field data (RUM) or a throttled profile would be needed before
  treating them as user-facing gates.
- INP is a proxy from a scripted burst, not a field metric.
- The desktop RSS sample is a single idle measurement on this machine; the
  engine comparison it descends from lives in
  [ADR 0006](../decisions/0006-browser-lanes-and-desktop-shell.md).
- Bundle sizes are per-artifact, not per-route: the repo gates the eager/lazy
  split (the Dev View chunk and the eager-shell prohibition) rather than
  attributing bytes to individual routes.
