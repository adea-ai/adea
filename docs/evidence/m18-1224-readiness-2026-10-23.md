## Findings

1. **The performance bundle gates pass at main.** PERF-01, PERF-02 and PERF-03 are `pass` at main, from the build above. The 2026-10-10 record could not give a verdict, because its bundle measurement was at another revision. The headroom on the total is thin: gzip 971,251 against a ceiling of 971,776 (525 bytes), raw 3,177,765 against 3,220,000, files 152 against 167. The ceilings in `scripts/client-bundle-budgets.mjs` are now 3,220,000 raw, 971,776 gzip and 167 files. [ADR-0010](../decisions/0010-performance-budgets-and-gates.md)'s table (2,350,000 raw, 700 KiB gzip, no file cap) is still stale and was not edited.
2. **The strict axe lane cannot complete at main.** The lane reaches surface 3 (Dev View at 320 px) and waits in `page.evaluate` until `document.getAnimations()` reports no running animation. The Dev View fixture's sidebar shows a worktree row `feature/example` with status "Running", and that row renders a `lucide-loader-circle` spinner (`animate-spin`, 1 s, infinite). It never stops, so the wait never ends. Two earlier attempts (bun, then node) ran more than 13 and about 8 minutes before being stopped, and the final attempt was stopped by `timeout 180` (exit 124). Surfaces 1 and 2 load, and in a separate probe a `wcag2a` axe run on the chat surface finished in 94 ms with zero violations, so the browser, server and axe injection work. ACC-01 is recorded as `blocked`. Nothing was scanned, nothing is claimed, and neither the lane nor the fixture was changed. Which change introduced a settled-animation assumption that no longer holds is not identified here; the 2026-10-10 run completed on a tree that differs from main in 29 app and package files.
3. **The keyboard certification suite fails one test at main, and it is a different test from the one that failed on 2026-10-10.** Test `cert 4.1.3: the workspace rail announces keyboard reorder moves` (spec line 388) expects the status text `Dev view moved to position 1 of 2` and receives `Dev moved to position 1 of 2`. `cert 2.5.8` passes now. Whether the rail's label or the test is out of date is not decided here. ACC-02 stays `fail`.
4. **`--run-unit` cannot be trusted for ACC-05.** The measurement script runs `bun test <files>` and ignores the criterion's own `command`, which carries `--conditions=browser`. Run that way, the two UI test files fail to load (`Client-only API called on the server side`, 0 pass, 2 fail, 0.3 s). With the criterion's command they pass 22 of 22. A first measurement with `--run-unit` recorded that false failure, so the committed measurement record was produced without `--run-unit` and the three unit criteria read `not-run`. The numbers are in the table above. The fix belongs in `scripts/readiness-evidence.mjs` and was not made, because this change is documentation only. The unit runs were done on a tree whose `apps/`, `packages/` and `scripts/` are main's, but they are not counted for main by the measurement record's rules.
5. **The A31 rollback fence tests pass at main on PostgreSQL 18.6.** 16 unit tests and 18 integration tests, all named `A31` or `A36` in `packages/db/tests/integration/lead-turn-rollback.test.ts`. OPS-06 is `partial`: this is the fence mechanics only. It is not a cohort rehearsal, it does not exercise the Control Plane fence consumer, and the populated migration rollback outcome record states that the rollback window is not declared safe.
6. **Presence probes changed since 2026-10-10 because code landed.** Rollback routing identifiers (OPS-05) and export identifiers (OPS-09) are now present on main, and the rollout and rollback document search (OPS-10) finds three documents. Presence is a search and not a behavior test. Metrics, operator controls, feature flags, the cleanup-gate identifiers and budget reservation (OPS-02 to OPS-04, OPS-08, COST-03, COST-04) are still absent, and so is the LangGraph reference count (COST-07).
7. **The inventory was edited.** The candidate list, three stale reasons (ACC-07, COST-02, OPS-06) and the OPS-06 method (now a recorded run) changed. The measurement record is pinned to the new inventory SHA-256, `0e23145c657b19da7a28bb3226028574bdf9bdda3369a906468532c3488eb53c`.
