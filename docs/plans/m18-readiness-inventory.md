## How to read the statuses

- **pass / fail**: a measured value compared with an explicit limit, at main.
- **present / absent**: an identifier was or was not found in product source at that revision. This is a search, not proof of behavior. `absent` does not prove a feature is missing, and `present` does not prove it works. For a candidate head, the same reading applies to that head only.
- **partial**: a passing test that covers only part of the criterion. The limit is written next to it.
- **not-run**: the criterion has evidence, but at a revision other than `--main`, or no evidence was supplied. The observed result and its revision are kept in the record. Only evidence at `--main` can give a verdict.
- **invalid**: evidence that fails its contract. Examples: an axe artifact that is not a complete strict scan; a check-client report that arrives with a nonzero exit; a recorded axe pass without its validated audit artifact. It never passes.
- **blocked**: an attempted run that did not complete. The reason and exit code are recorded.
- **measured**: a recorded run, with its command and result.
- **not-measured**: measurable in principle but not run here. The command is in the inventory.
- **unavailable**: needs data, a person or a decision that this repository and session do not have. No value is estimated.
- **not-claimed**: this leaf makes no claim.

## Findings

1. **The bundle ceilings pass at main, with almost no gzip headroom.** Total gzip is 971,251 against a ceiling of 971,776, a margin of 525 bytes. Raw is 3,177,765 against 3,220,000 and the file count is 152 against 167. Startup (666,403 raw, 218,172 gzip) and every view ceiling pass with room. The ceilings now in `scripts/client-bundle-budgets.mjs` are not the ones in ADR-0010's table (2,350,000 raw, 700 KiB gzip, no file cap), which is stale and was not edited. A change that adds more than 525 gzip bytes to the total will fail the gate.
2. **The strict axe lane (ACC-01) cannot complete at main.** At surface 3 it waits for every document animation to stop, and the Dev View fixture's "Running" worktree row renders an infinite spinner. Nothing was scanned. The 2026-10-10 results (zero violations on 10 surfaces, at a different tree) are history and say nothing about main. Neither the lane nor the fixture was changed.
3. **The keyboard suite (ACC-02) fails one of 12 tests at main:** `cert 4.1.3`, the workspace rail's reorder announcement ("Dev moved to position 1 of 2" against the expected "Dev view moved to position 1 of 2"). `cert 2.5.8`, the 2026-10-10 failure, passes. Neither failure is decided as a regression or a stale test.
4. **`--run-unit` ignores each criterion's `command`.** It runs `bun test <files>`, which fails ACC-05 to load (the criterion's command carries `--conditions=browser`). The fix is a script change and was not made here. The committed measurement record was produced without `--run-unit`; hand runs at main's code are reported in the criteria table.
5. **The A31 rollback fence tests pass at main** (16 unit, 18 integration on PostgreSQL 18.6). OPS-06 is `partial`. That covers fence mechanics, not a cohort rehearsal, not the Control Plane consumer, and not a declaration that the rollback window is safe.
6. **Rollout and rollback guidance now has one entry point,** [m18-rollout-rollback-guidance](m18-rollout-rollback-guidance.md). It indexes existing records and lists the decisions that are still open. OPS-10 stays `present` because a document search finds files; it does not mean an approved runbook exists. The decisions it leaves open (operator identity for the rollback window, cohort choice, production lock durations, RPO and RTO, the Control Plane fence consumer, native session restore authority) are owned by people outside this repository's record.
7. **Cost is not measured.** Budget reservation and cost-state identifiers are still absent on main (COST-03, COST-04). The only zero-model-call test covers the structural-lead setup path (COST-01, partial by its own scope). Metering (COST-05) and billing reconciliation (COST-06) are unavailable.
8. **Operations mechanisms are mostly still absent on main.** Metric, operator-control, feature-flag and cleanup-gate identifiers are absent. Rollback routing identifiers (OPS-05) and export identifiers (OPS-09) are present, which is a search result and not a behavior test.
9. **The runtime latency targets are not approved.** PERF-06 (p95 admission at or below 1 s, scheduling at or below 2 s) is a proposal awaiting FOUNDATIONS approval. No benchmark exists, so nothing is measured.
10. **Daily-driver readiness is not measured.** OPS-11 (the owner using the candidate) is unavailable to an agent. The stable-artifact chat acceptance on a fresh profile (#536) and the packaged and native lanes need the owner's Mac, and keychain, LaunchServices and Accessibility are separate gates.

## Reproduce

```sh
bun install --frozen-lockfile                   # bun 1.4.4, the repository pin
bun run --cwd packages/types build
bun run build                                   # whole workspace, then the web build is cheap
bun run --cwd apps/web build
bun run --cwd apps/web start:check-bundle       # check-client report on line 2; wrap it as below
node scripts/readiness-evidence.mjs check
node scripts/readiness-evidence.mjs measure \
  --main fed9548c5b1f7bbf319872940a0bd7de4055dbde \
  --candidate 1548=5d5a8e42044baab17b30e17c9e76f72cf51e267e \
  --candidate 1549=658b262312cbddb576b17190db2e768250d6edc8 \
  --candidate 1550=0c9110f4d407f6406711c4c8460240943eac0b82 \
  --bundle docs/evidence/m18-1224-client-bundle-main-2026-10-23.json \
  --recorded docs/evidence/m18-1224-recorded-runs-2026-10-23.json
```

Browser rows need a Dev View dev server against a PostgreSQL on `127.0.0.1:55432` (the port `wrangler.jsonc` fixes for the local Hyperdrive binding); the commands are in the run record. Pass one `--candidate <pr>=<sha>` per row in the candidate table. Each SHA must be in the local object store (`git fetch origin <branch>`).

Every evidence file names its `revision` (a full 40-character commit SHA), its `command` and its `exitCode`. The bundle file wraps the check-client report as `{ revision, command, exitCode, report }`. The axe file, when a lane completes, wraps the audit artifact as `{ revision, command, exitCode, artifact }`. The recorded-runs file is keyed by criterion id, and each entry carries the same three fields. `measure` refuses input that does not meet this contract. Only evidence whose revision equals `--main` can give a verdict. `--run-unit` needs a clean tracked tree and labels its results with HEAD, and it does not pass a criterion's own flags (finding 4), so it is not used for this record.

The `check` command validates the inventory and exits non-zero on any error. The measure command rewrites `docs/plans/m18-readiness-measurements.json`.
